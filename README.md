## 功能全景

- **人机对弈**：入门 / 进阶 / 高手（深度搜索）三档 AI，可切换先手
- **残局挑战**：24 道「一步制胜」与「唯一防点」残局，按破解用时评星（三星 ≤ 6s）
- **每日残局**：按日期轮换一题，首破金币翻倍
- **段位系统**：青铜 → 白银 → 黄金 → 铂金 → 钻石 → 王者，按 AI 棋力加减积分
- **金币经济**：胜局赚金币，提示（5）与悔棋（3）消耗金币，每日签到 +20
- **棋盘皮肤**：胡桃木（默认）/ 玄墨 / 樱庭，后两者金币解锁
- **对局复盘**：终局后逐手回放，支持键盘方向键
- **成就系统**：10 项成就（连胜、快棋、解题等），解锁即时横幅
- **生涯统计**：总对局 / 胜率 / 最快取胜 / 累计金币
- **体验细节**：合成音效（黑白异音色）、落子回弹动画、胜利连线呼吸、AI 台词、纸屑结算、震动反馈、战绩分享

## 技术架构

```
┌────────────────────────────────────────────────────┐
│ index.html          页面结构（语义化骨架）           │
├────────────────────────────────────────────────────┤
│ css/style.css       设计令牌 + 分区样式             │
├────────────────────────────────────────────────────┤
│ js/app.js           应用层：交互/渲染/音效/成长系统   │
│   ├── 生涯存档      localStorage 单键，版本化合并    │
│   ├── 音效系统      WebAudio 振荡器合成，零资源文件   │
│   ├── 渲染          Canvas 2D，rAF 按需运转          │
│   └── 残局/复盘     对局快照可无损恢复               │
├────────────────────────────────────────────────────┤
│ game.js             纯逻辑引擎（零 DOM，三端复用）   │
│   ├── winLineAt     胜负判定（仅查落子点）           │
│   ├── analyzePoint  棋型模式识别评估                 │
│   └── bestMove      战术硬规则 → 综合评分 → α-β 搜索  │
├────────────────────────────────────────────────────┤
│ puzzles.js          残局题库（生成器产出）           │
│ tools/gen-puzzles.js  生成器：随机布局 → 引擎验证唯一解 │
│ utils/engine.js     小程序端引擎（同一份代码）        │
└────────────────────────────────────────────────────┘
```

分层原则：**引擎不知道界面的存在**。`game.js` 只暴露 `createBoard / winLineAt /
analyzePoint / bestMove` 等纯函数，因此它可以在 Node 里被单元测试、在构建期
验证残局题库、在微信小程序中原样复用——这也是测试策略成立的前提。

## AI 算法说明

### 1. 棋型模式识别（评估的基石）

在候选点四个方向各取 9 格窗口，把己方/空/对方编码为 `1/0/2`，与棋型库做
子串匹配（要求匹配段覆盖中心）：

| 棋型 | 模式示例 | 分值 |
|---|---|---|
| 连五 | `11111` | 10,000,000 |
| 活四 | `011110` | 400,000 |
| 冲四（含跳四） | `11101` `10111` `11011` … | 60,000 |
| 活三（含跳活三） | `011100` `011010` … | 50,000 |
| 眠三 / 活二 / 眠二 | … | 3,000 / 2,500 / 300 |

跳子形态（如 `●●●·●`）单独建模，评估不会漏掉「隔一格」的杀招。

### 2. 战术硬规则（下限承诺）

对每个候选点分别计算「我方落此」与「对方落此」的棋型价值，然后按
**我方成五 > 挡对方成五 > 我方活四 > 挡对方活四** 的优先级直接决策。
这一层与难度无关——它保证 AI 不会犯最低级的错误，也使得「能赢必赢、
该挡必挡」成为可被单元测试断言的行为（见 test.js §2–4）。

### 3. α-β 剪枝搜索（高手难度）

- 根节点取综合评分前 12 的候选点，逐点做深度 4 的 negamax；
- 着法按「进攻分 + 防守分」排序，配合 α-β 窗口提高剪枝率；
- 叶子用全盘 5 格滑窗评估（己方 1/2/3/4 子计数计分，减去对方同权值 ×1.06 偏防守）；
- 节点数上限（40 万）兜底，中盘实测思考 ~100ms；
- 胜负分 `1e9 - ply` 使 AI 偏好最快取胜、最慢认负。

### 4. 随机性与可复现

入门难度在前三名候选中加权随机；引擎暴露 `setRandom(fn)`，测试注入固定
种子的 LCG，使整局结果可复现、断言稳定（test.js §5）。

## 残局内容管线

`tools/gen-puzzles.js` 按「连四堵一端 / 跳四 / 双杀十字」三类模板随机布子，
每一题必须通过引擎验证：

1. 杀点唯一（全盘扫描恰有一个成五点）；
2. 对方无杀（题面干净）；
3. 走答案后确实连五。

生成后由 test.js §7 再次全量复验，并交叉验证：**hard 引擎在全部「一步制胜」
题上都必须选中答案**——生成器与 AI 互为对方的质量保证。

## 测试策略

```
node test.js    # 22 项断言，无需任何依赖
```

- 胜负判定：四方向五连、边界、被拦截的四连不误判
- 战术保证：三档难度能赢必赢 / 挡冲四 / 挡跳四 / 挡活三
- 对弈完整性：整局自弈不崩溃、不落非法子
- 性能：困难模式中盘思考 < 2s（实测 ~100ms）
- 题库完整性：答案唯一 + 引擎交叉验证

## 工程化

- **CI**：GitHub Actions 在每次 push 时运行全量测试（.github/workflows/test.yml）
- **部署**：GitHub Pages 直发 main 分支；另有 ZCode Sites 托管（纯静态，双 CDN）
- **并发**：AI 全部在玩家浏览器本地运行，服务器只分发静态文件，千人并发无压力
- **微信小程序**：`wechat-miniprogram/` 为同一项目的移植版，引擎原样复用，
  界面层用 WXML/Canvas 重写（详见该目录 README）

## 本地开发

```bash
node test.js              # 运行测试
node tools/gen-puzzles.js # 重新生成残局题库
node tools/dev-server.js  # 本地预览 http://127.0.0.1:8767
```

无构建步骤、无第三方运行时依赖——打开 `index.html` 即可玩。
